# دريس

لعبة شعبية على لوحة 3×3: لكل لاعب ثلاث قطع، ويفوز من يصفّها في خط **أفقي أو عمودي**.
لعبة متصفح بالكامل (HTML + CSS + JavaScript) بلا أي مكتبات أو صور أو ملفات صوت خارجية:
كل الرسومات مرسومة برمجياً على Canvas، وكل الأصوات مولّدة بـ Web Audio API.

## التشغيل

دريس موقع ثابت: لا تثبيت ولا خطوة بناء، ويعمل في أي متصفح حديث على الكمبيوتر أو الجوال.

### النشر على الإنترنت

ارفع المجلد كما هو إلى أي استضافة مواقع ثابتة (مثل GitHub Pages أو Netlify أو Cloudflare Pages)
ثم افتح رابط الموقع.

### التجربة على جهازك

المتصفحات تمنع تحميل وحدات JavaScript من ملف محلي (`file://`)، لذلك شغّل خادماً محلياً بسيطاً داخل المجلد:

```bash
python -m http.server 8000
```

ثم افتح <http://localhost:8000>.

## أوضاع اللعب

### كلاسيك
اللعبة الشعبية كما هي: قرعة، ثم صفّ، ثم تحريك، ضد الكمبيوتر بأربعة مستويات.
في «سهل» و«متوسط» يتوفّر زر **تلميح**، ويُظلَّل باللون الأحمر المربعُ الذي يهدّدك منه الخصم.
بعد كل مباراة يمكنك فتح **تحليل المباراة**، فيقيّم كل قرار من قراراتك مقارنةً باللعب المثالي:
ممتاز، أو فوز أبطأ، أو فرصة ضائعة، أو خطأ قاتل، مع اقتراح الحركة الأفضل.

### رحلة دريس (المراحل)
21 مرحلة في أربعة فصول. لكل فصل لوحته وقاعدته الخاصة:

| الفصل | اللوحة | القاعدة |
|---|---|---|
| 1. البداية | الخشب | القواعد الكلاسيكية |
| 2. خطوة خطوة | الرمل | تتحرك القطعة خطوة واحدة إلى مربع ملاصق (حتى قطرياً)، ومن لا يجد حركة يخسر |
| 3. القطري يُحتسب | الطباشير | الخط القطري فوز أيضاً |
| 4. الحجر في الوسط | الرخام | المركز مغلق بحجر والحركة خطوة أفقية أو عمودية. هنا يفوز من يصفّ ثانياً إن لعب بإتقان |

أنواع المراحل:
- **مباراة**: مباراة كاملة.
- **لغز**: افُز خلال عدد محدد من الحركات، والخصم يدافع دفاعاً مثالياً.
- **دفاع**: اصمد من وضعية خطرة.
- **تحدّي الصفّ**: الخصم صفّ قطعه أولاً، وعليك أن تصفّ قطعك بحيث لا تخسر.
- **الزعيم**: خصم نهاية الفصل.

لكل مرحلة ثلاث نجوم: الأولى لتحقيق الهدف، والثانية لعدم استخدام التلميح، والثالثة لمكافأة المرحلة
(المحاولة الأولى، أو الفوز السريع، أو هزيمة الزعيم). كل مرحلة تفتح التي بعدها، وزعيم كل فصل يفتح الفصل التالي.

كل الألغاز والتحديات مولّدة من الحل الكامل للعبة، فحلّها مضمون. ويتحقّق اختبار آلي من أن كل مرحلة
يمكن إكمالها باللعب المثالي، وأن كل لغز يمكن أن تخسره بحركة خاطئة.

## الاختبارات

- في المتصفح: افتح <http://localhost:8000/tests/> (83 اختباراً).
- أو عبر Node.js (إن كان مثبتاً): `node tests/run.js`.
- اختبار شامل للواجهة يلعب مباريات كاملة (من القرعة حتى شاشة النتيجة) في كل المستويات بالفأرة أو باللمس،
  بالسحب والإفلات وبالنقر، داخل Chrome بدون واجهة (يتطلب Chrome و`pip install websocket-client`):

```bash
python tests/e2e/play.py desktop easy,medium,hard,expert marble butt
```

```bash
python tests/e2e/play.py mobile easy,medium,hard,expert neon pit
```

ولعب رحلة دريس كاملةً عبر الواجهة. يشمل ذلك: إفشال لغز عمداً، واستخدام التلميح، وفتح التحليل،
والتحقق من النجوم وفتح المراحل:

```bash
python tests/e2e/play.py campaign desktop
```

تغطي الاختبارات:
- **القواعد:** الفوز بالأفقي والعمودي فقط (القطري لا يُحتسب في الكلاسيك)، وعدم احتساب أي خط أثناء الصفّ،
  وصحة الحركات (الدور، الملكية، المربع الفارغ، المرحلة)، والتعادل بالتكرار ثلاث مرات وبمرور 50 حركة،
  ونقاء الدالة (لا تعدّل الحالة الأصلية).
- **القواعد الخاصة بالفصول:** الحركة لمربع ملاصق، والأقطار، والمربع المغلق، وخسارة اللاعب المحاصَر.
- **الحل والذكاء الاصطناعي:** صحة الحل الكامل لكل قاعدة، ومستويات الذكاء الاصطناعي، والتحليل.
- **المراحل:** محتواها وإمكانية إكمالها.

## بنية الكود

```
index.html            هيكل الشاشات
css/style.css         التصميم (RTL، جوال وكمبيوتر)
js/core/rules.js      منطق اللعبة الصافي: applyAction(state, action) → newState (مع القواعد الخاصة)
js/core/rng.js        مولّد أرقام عشوائية قابل للبذر
js/ai/solver.js       الحل الكامل (retrograde analysis) لكل قاعدة: «خبير» والتلميح والألغاز
js/ai/search.js       Minimax + Alpha-Beta بعمق محدود لمستوى «صعب»
js/ai/ai.js           اختيار الحركة حسب المستوى (يشمل مرحلة الصفّ) وأفضل حركة للتلميح
js/ai/review.js       تحليل المباراة: تقييم كل قرار مقارنةً باللعب المثالي
js/campaign/          الفصول والمراحل، ومولّد الألغاز والتحديات، والأهداف والنجوم، والتقدّم
js/game/match.js      إدارة الأدوار بين اللاعبين
js/game/players.js    لاعب محلي، كمبيوتر، ولاعب عن بُعد (نقطة توسعة)
js/render/            الكاميرا، الثيمات الخمسة، رسم القطع، المشهد والحركات
js/audio/             المؤثرات الصوتية والموسيقى الخلفية
js/ui/                القائمة، القرعة، شريط المعلومات، الإدخال، النتيجة، التخزين
js/main.js            ربط كل ما سبق
tests/                الاختبارات
```

## الذكاء الاصطناعي

| المستوى | الأسلوب |
|---|---|
| سهل | عشوائي في الغالب، وأحياناً يلاحظ فوزاً أو صدّاً |
| متوسط | يفوز إن استطاع، يصدّ فوزك المباشر، وإلا عشوائي |
| صعب | Minimax مع Alpha-Beta بعمق 3 وتقييم إرشادي |
| خبير | لعب مثالي من الحل الكامل للعبة |

مرحلة التحريك فيها 1680 لوحة × جهتان = 3360 حالة فقط، فتُحلّ كلها عند بدء التشغيل في أجزاء من الثانية،
وتُحلّ شجرة الصفّ فوقها. **نتيجة الحل: اللعبة تعادلٌ مع اللعب المثالي من الطرفين**،
لذلك لا يخسر «الخبير» أبداً، وأفضل ما يمكنك تحقيقه أمامه هو التعادل. وعند تساوي الخيارات
يختار الحركة التي تترك لك أكبر عدد من الأخطاء الممكنة.

## اللعب أونلاين أو عبر الواي فاي/البلوتوث لاحقاً

المنطق منفصل تماماً عن الواجهة:

- الحالة والحركات كائنات JSON عادية، و`applyAction` دالة نقية تتحقق من كل حركة.
- `Match` يطلب الحركة من اللاعب صاحب الدور عبر `requestAction(state, signal)` أياً كان نوعه.
- `RemotePlayer` في `js/game/players.js` يحتاج فقط ناقلاً فيه `send(message)` و`onMessage(handler)`
  (WebSocket أو WebRTC DataChannel أو Web Bluetooth)، ويُرسل حركات اللاعب المحلي تلقائياً عبر `observe`.
- القرعة يمكن أن يفرضها المضيف: `runToss({ forced: 0 | 1 })`.
